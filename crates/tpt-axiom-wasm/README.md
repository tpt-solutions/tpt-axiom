# tpt-axiom-wasm

WASM bindings behind the browser playground (`docs/playground/`). Build with:

```sh
wasm-pack build crates/tpt-axiom-wasm --target web --out-dir ../../docs/playground/pkg
```

Then serve `docs/playground/` statically (e.g. `python -m http.server`) and
open it in a browser.

## What runs in the browser

- **Circuit inspection** — the IR description and R1CS shape of the demo
  circuits.
- **Uncertainty demos** — minimum-variance fusion, delta method vs. Monte
  Carlo.
- **Groth16 proof verification** — `verify::groth16_verify` takes a compressed
  verifying key, a compressed proof and the public inputs as hex, and answers
  `valid` / `invalid` locally. Proving stays native (the prover stack is not
  distributable to WASM), but verification is just a pairing check, so it is.

The demo proof shipped in `verify::DEMO_VK_HEX` / `DEMO_PROOF_HEX` is a real
proof of `result == a * k` (with `k` secret) over the public inputs
`a = 2, result = 8`, generated by the `freshly_proven_fixture_verifies_through_the_browser_path`
test. Change the claimed result to 9 in the page and the verdict flips to
`invalid`.

## Tests

`cargo test -p tpt-axiom-wasm` covers the honest round trip, the near-miss
public input, a tampered proof, a truncated proof, malformed hex and a wrong
public-input count, and re-proves a fresh fixture through the same function the
page calls.

`node docs/playground/smoke.mjs` runs the *built* WebAssembly module under Node
(the same check CI runs): honest → `valid`, near-miss → `invalid`, truncated →
throws.
